# 第二轮界面调整：已对齐的需求

与仓库主人对齐于 2026-10-30，已全部确认，作为一个目标执行。

## 1. 长按与下拉菜单：液态玻璃上下文菜单（方案 A）

- 长按歌曲行：被按的行轻微浮起（放大约 3%、加阴影），其余页面轻度模糊并压暗。
- 菜单面板是液态玻璃（与底栏同一个 Backdrop 库），从手指位置以弹簧动画缩放展开；分组、细分隔线、图标靠右，危险操作红色。
- 按住不松手滑到某一项、松手即执行（同 iOS）；点空白处收起，收起有反向动画。
- 标题下拉、「更多」菜单、搜索结果的长按菜单统一用这套样式。
- 实现：
  1. 现在的菜单是系统弹窗（单独的窗口），玻璃取不到页面内容，改成页面内的覆盖层，用 `drawBackdrop` 画面板。
  2. 打开时页面整体轻度模糊、压暗，被按的行在覆盖层里重画一份，浮起放大；玻璃面板从手指位置弹簧展开。
  3. 按住时手指的位置高亮其下的菜单项，松手执行；直接点菜单项同样执行。
  4. Backdrop 库没有现成的菜单组件，借鉴其示例：玻璃对话框（`DialogContent`：较强的模糊与带 depthEffect 的 lens）、控制中心的弹簧进场（`ControlCenterContent`）、按压高光（`InteractiveHighlight`）。改编的示例代码保留 Apache-2.0 出处（同 `ui/glass/`）。

## 2. 重新打开后恢复上次播放

- 切歌、暂停、应用进入后台时保存：当前列表（槽位）、歌曲、播放位置（与桌面 `useLibraryLoad` 按槽位保存 currentTrackIndex / currentTime 一致）。
- 启动时把这首歌载入播放器、停在保存的位置（不自动播放），控制栏显示它，列表滚动到它。
- 打开的歌单也要保存（歌单来源与 id），启动时向音乐源重新获取；失败（无网络、未登录）就不恢复歌单。

## 3. 控制栏常驻；没有歌曲时

- 控制栏始终显示。没有歌曲时：封面用 LyricsAdapter 的应用图标，标题「LyricsAdapter」，副标题「轻点歌曲开始播放」（不出现 unknown / 未选择曲目）。
- ▶ 从当前列表第一首开始播放；▶▶ 变灰不可点。

## 4. 快速回到顶部

- 安卓状态栏属于系统界面（SystemUI），点击会被系统拿去下拉通知栏，没有公开 API 让应用收到；只能靠系统自身的「点状态栏回顶部」（部分国产系统有，原理是给前台应用发无障碍滚动动作）。
- 只做一个入口：双击列表的标题栏区域（大标题与子标题一带）回到顶部，带滚动动画。

## 5. 搜索移到列表页

- 底栏去掉搜索；「资料库」改名「播放列表」。
- 搜索框放在子标题下方，横跨列表宽度；与底栏、菜单同一层级（浮在列表之上的玻璃层），不随列表滚动，列表在它下面滚过。具体视觉由实现者平衡。
- 输入时，搜索框下方原地切换为搜索结果（本地、云端、各音乐源、歌单，与现在相同），「取消」回到列表。

## 6. 底栏合并成一行

- 底部固定一行：左边圆形页面按钮，右边控制栏；两者都加高（约 60dp），控制栏相应变窄。不再有滚动时收起、浮起的效果。
- 圆形按钮显示当前页面图标。点按向上弹出玻璃气泡（「播放列表」「设置」），点气泡切换；也可以按住不放、拖到气泡上松手切换。
- 控制栏里的封面往右移一些（现在太靠左，与胶囊的圆角不协调）。

## 7. 专注模式

- 控制区自动隐藏的时间从 1 秒改为 3 秒。
- 现在切歌之后控制区会很快消失（比平时更快），要查明原因；任何情况下（包括切歌后、点按钮后、拖动进度或音量后）都统一在最后一次操作 3 秒后才隐藏。
- 横屏：
  - 收起专注模式的抽屉把不再固定在封面上方，改到整页顶部、水平居中（放在顶部安全区一带，不压在两栏内容上）。
  - 歌词区和左栏（封面与元数据）一样高、上下对齐，不再偏矮。

## 8. 其他页面的横屏适配

横屏手机宽度富余、高度很矮（约 370dp），思路是省高度、内容不拉满整屏：

- 列表与搜索：内容宽度设上限并居中；大标题在横屏下缩小（约 24sp），子标题与搜索框收进更紧凑的标题区，留出列表高度；海报墙沿用现有的宽屏分带排列。
- 底栏一行（页面按钮 + 控制栏）最大宽度约 520dp，居中，不拉满整屏。
- 设置：内容最大宽度约 600dp，居中。
